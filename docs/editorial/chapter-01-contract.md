# 第 01 章编辑契约

## 读者起点与终点

读者可以把文本交给一个生成模型并取得结果，知道 Transformer、token 和 Attention 这些词，但未必能把模型语义还原为服务端事件。

读完正文后，即使移除所有实践，读者也应能独立完成四件事：区分一次 API 请求、一次模型前向和一个生成步；从因果 Attention 推导 prefill 与 decode 的形状；重建 logits 到客户端可见文本的事件边界；审查任一终止路径是否停止计算、停止发送并安全释放资源。

## 贯穿算例

全章只使用请求 R：输入经一个假想 tokenizer 得到四个 prompt token `x1…x4`，模型依次选择 `y1`、`y2`、`y3` 和 `<eos>`，开启流式输出，最多生成 8 个 token。符号只表达位置和依赖，不冒充任何真实模型的切词或输出。

正常路径与中途取消路径共享这一个算例。取消变体只改变一个条件：`y2` 的发送提交点附近到达取消信号。

## 首次出现时必须解释的术语

| 术语 | 正文第一次承担的解释 |
| --- | --- |
| token | 模型词表中的离散编号，不等同于汉字、单词或网络输出片段 |
| 自回归 | 下一个 token 的分布依赖此前 token，因此输出之间存在不可消除的顺序依赖 |
| logits | 模型对词表候选给出的未归一化分数，不是已选 token，也不是文本 |
| causal Attention | 每个位置只能读取自己及之前位置，使同一已知序列内的位置可并行、未知的未来位置不能并行 |
| prefill / decode | 同一模型执行循环在完整已知前缀和单个新增位置上的两种执行形状 |
| KV state | Attention 为历史位置产生、后续步仍需读取的状态；本章只建立所有权，不展开分配策略 |
| streaming | 服务端在请求结束前分批提交可见输出；它改变可见时间，不改变自回归依赖 |
| terminal reason | 请求为何结束，与请求当前执行阶段分离保存，避免状态枚举失控 |

## 事实边界

- 稳定原理：自回归条件分解、因果 Attention 的依赖关系、采样在模型前向之外、状态资源必须沿所有终止路径释放。
- 实现选择：张量是否只物化最后位置的 logits、增量解码器如何缓冲字符、取消以何处为线性化点、流对象由谁关闭。
- 留待测量：prefill 或 decode 谁更耗时、缓存是否提高某个设备上的吞吐、流式提交粒度对延迟的影响。本章不得给出无基准的性能结论。
- 版本事实：本章不依赖 vLLM 或 SGLang 的类型名、默认值和当前源码布局。

## 规格落点

| 规格要求 | 正文落点 |
| --- | --- |
| 现象—旧模型—矛盾—机制 | 从“一次请求就是一次 forward”的合理直觉进入多步生成 |
| prefill / decode 由依赖推出 | “同一循环的两种形状”中的位置依赖、张量形状和手算轨迹 |
| 模型执行与采样、流式分离 | “生成不等于可见”中的事件链和四步时间线 |
| 完整终止与资源所有权 | “状态从哪里来”及“结束不是一个瞬间” |
| 最小实现而非最佳实践 | 末节执行器伪代码、接口合同和明确省略项 |
| 实践可移除 | 正文不导入任何实践组件；完成连续阅读审查后才决定是否增加 |
| 掌握使用解释证据 | 后续综合题要求时间线、异常路径和设计审查，不记录浏览完成度 |

## 人工审阅问题

1. 去掉样式连续阅读时，五个标题是否各自改变了正在解决的问题？
2. 每个术语是否在读者已经看到需要它的矛盾之后才出现？
3. 每项数据结构、控制流或所有权是否能回指前文约束？
4. 删除全部实践后，读者是否仍可重建正常与取消路径？
5. 是否出现“通常更快”“最佳实践”一类缺乏条件或证据的结论？

## 样板验证后可沉淀的规则

- 一条贯穿算例可以同时承载模型依赖、可见输出、状态和资源四条记录；只有当前问题改变时才切换记录视角。
- 术语第一次出现的位置应由矛盾决定，不需要另建术语卡；同一概念后续只补充新边界。
- 工程接口应能逐项回指语义约束，并同时写出维护的不变量、增加的成本和仍未解决的问题。
- 动态实践必须先形成书面取舍，说明它强迫学习者提交什么预测，以及删除实践后正文为何仍成立。
- 自动检查适合发现结构破损和状态不变量错误；标题是否重复、过渡是否突兀和性能判断是否越界仍保留人工审阅。
- 当依赖、时间或所有权变化难以从静态段落中直接观察时，应在概念形成后插入可暂停、可单步的图示；图示改变一个变量并同步显示受影响的状态，不作为装饰背景。

这些规则来自第 01 章样板，不规定后续章节必须使用五个标题、一个实践或同样的页面模块。
