## 必须实测的判断

以下问题在本章只能提出观察需求，不能由逻辑拍给出结论：

- 不同调度策略对真实 TTFT、逐 token 间隔、尾延迟、吞吐和 goodput 的影响。
- prefill 与 decode 在真实硬件上混合执行的形状、成本与干扰。
- 真实调度器的准入、抢占与优先级在具体负载下的行为。
- 教学拍数与任何真实时间量纲的换算关系（不存在这种换算）。

真实结论必须沿用第 00 章的测量合同：固定请求集合与生成工作量，记录观察者和完成事件，保留原始事件、失败与环境信息，再限定结论适用范围。

## 确定性教学模型假设

任务组 1 的调度领域模型只用于形成可复核的因果轨迹：

- 模型、请求与块池完全延续：128 bytes/token、`R-long`/`R-short`/`R-late`、6 块 × 4 unit；准入按第 04 章规则（prompt+1 token 所需块数 ≤ 空闲块）。
- 每拍至多一份设备工作：拍内顺序为到达与准入检查 → 计算可运行集合 → 按策略选择 → 执行 → 完成者释放块。这是教学抽象；真实系统一次执行可混合多种工作（如 chunked prefill），留作实现示例之外的未讲内容。
- decode 组把全部可 decode 成员合为一次执行，每人 1 个有效 token，无 padding；prefill 一次执行一个新请求。
- 两种策略：prefill 优先（新请求 prefill 先于 decode 组，FIFO）与 decode 优先（decode 组先于等待中的 prefill）。
- 逻辑拍是离散事件刻度，不对应毫秒、GPU cycle 或等长执行区间；字段名与界面禁止出现耗时、带宽或利用率语义。
