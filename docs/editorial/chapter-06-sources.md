## 必须实测的判断

以下问题在本章只能提出观察需求，不能由教学计数给出结论：

- 各种准入与抢占策略对真实 TTFT、尾延迟、吞吐、goodput 与公平性的影响。
- 重计算与换出在具体模型、形状与硬件上的真实开销对比。
- 水位、队列上限与优先级参数在真实负载下的最优区间（不存在跨负载的普适值）。
- 持续过载下队列增长与服务降级的真实动态（教学池的队列深度不是真实排队论）。

真实结论必须沿用第 00 章的测量合同：固定请求集合与生成工作量，记录观察者和完成事件，保留原始事件、失败与环境信息，再限定结论适用范围。

## 确定性教学模型假设

任务组 1 的过载领域模型只用于形成可复核的因果轨迹：

- 模型、块池与拍内顺序完全延续第 03—05 章：128 bytes/token、6 块 × 4 unit、prefill 优先、每拍至多一份设备工作。
- 突发工作量：`P-a`/`P-b`（t0，5+3）、`P-c`（t1，5+3）、`P-d`（t2，3+2）；t1 末空闲恰为 0。
- 四条策略：无界排队（free ≥ need 即准入，否则排队重试）；按满拒绝（free − need ≥ 0，否则立即拒绝）；水位拒绝（free − need ≥ W，W=1）；抢占重计算（新请求到达拍若 free < need 则抢占“最近开始生成者”，等待中的重试请求安静排队以避免震荡，受害者以 prompt 加已生成 token 重算恢复）。
- 重计算恢复按 write-through 约定计数：重新 prefill 的 token 数 = prompt + 被抢占时已生成数，恢复步本身产出下一个 token。
- 抢占受害者规则是教学假设并显式登记；真实框架按优先级与到达时间选取（版本锁定示例）。
- 拍数、队列深度、被拒数、被抢占数与重计算 token 数是证据边界内的记账；字段名与界面禁止出现耗时、带宽或利用率语义。
