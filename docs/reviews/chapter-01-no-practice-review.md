# 第 01 章无实践版本审查

审查对象：`src/content/chapters/single-request.mdx`。本轮只判断正文是否独立成立，不以将来的状态轨迹组件补救解释缺口。

## 连续推导结果

正文使用请求 R 到底，没有中途换成另一个更方便的算例。五个标题分别改变正在解决的问题：API 调用和模型执行边界、已知位置造成的两种执行形状、生成与可见输出边界、跨步状态与所有权、异常终止与最小实现。prefill 和 decode 没有拆成并列术语页；logits、sampling、停止、解码和 streaming 也保留在同一事件链中。

首次术语检查通过。token 出现在字符数与模型输入不可互换的矛盾中；自回归出现在 `y2` 依赖尚未产生的 `y1` 之后；prefill、decode 在位置依赖和形状已经建立后命名；KV state 在避免历史重算之后出现；terminal reason 在阶段枚举开始膨胀时引入。移除伪代码仍能从前文推导这些概念。

## 算例与事件核对

R 的 prompt 长度为 4。prefill 消费 `x1…x4`，KV 从 0 增至 4，并用末位置 logits 选择 `y1`。三次 decode 分别消费 `y1`、`y2`、`y3`，KV 增至 5、6、7，并依次选择 `y2`、`y3`、`<eos>`。`<eos>` 被选择后停止，没有作为下一次模型输入；所以生成 token 数为 4，KV 长度为 7，二者没有被误写成同一计数。

可见输出表把首 token 选择、首片段提交、生成终止和资源释放分开。取消邻近发送的两个合法顺序也都能闭合：取消先取得终止权时不提交 `y2`；发送先越过提交点时允许 `y2` 可见，但禁止后续 decode。两条路径最终都等待在途工作到达安全点、只释放一次 KV 并只关闭一次流。

## 工程回链与边界

请求上下文字段均有理论来源：生成历史服务于下一步输入和长度停止，KV handle 服务于历史复用，decoder tail 服务于 token/字符边界，terminal reason 服务于不同结束合同。伪代码中的模型、输出策略、发送许可和安全释放也能回到正文中的依赖、停止、提交点和在途资源。

正文没有声称同步循环是最佳实践，也没有从形状直接推出性能。单请求、同步发送、抽象设备等待和未设计 KV 分配均明确作为限制转交后续章节；没有提前给出调度或分页机制答案。
