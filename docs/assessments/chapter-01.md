# 第 01 章综合验收

这些问题不按小节复述术语。答案应给出可检查的事件、因果和所有权，不以提到 prefill、decode 或 KV 等词本身计分。

## 1. 重建一条新时间线

请求包含 6 个 prompt token，最多生成 3 个 token，非流式返回；模型第三次选择结束 token。请列出实际发生的模型执行，分别写出每次新增输入、执行前后 KV 长度、何时确定终止，以及客户端何时首次得到文本。

检查标准：区分一次 API、prefill 和后续 decode；不能把被选择但未再次送入模型的结束 token 计入 KV；非流式合同下，首 token 选择不等于客户端可见。

## 2. 分析异常终止

一次 decode 已提交给设备，此时 deadline 到期；设备稍后正常返回一个 token，但输出流还未写入。给出合法事件顺序，并说明生成结果、输出流、KV 和结束原因的处理。

检查标准：超时先取得终止权后不再提交该 token，也不启动下一步；在途计算必须先到达安全点才能释放其输入资源；结束原因保持 `timed_out`，后到的成功结果不能覆盖；流与 KV 各收束一次。

## 3. 审查朴素执行器

某实现每步按“检查取消—采样—异步发送—若停止则退出”执行，`finally` 中立即释放 KV，但发送任务和设备任务都可能尚未完成。找出至少三个不能由现有顺序保证的性质，并提出接口层修正，不要求写框架代码。

检查标准：答案应覆盖检查与发送之间的竞态、停止串可能在发送后才被发现、KV 被在途工作读取时提前释放、异步发送结果不明确或流重复关闭中的至少三项；修正应说明原子提交/终止顺序、输出安全前缀以及释放前安全点，而不是再散落几个布尔检查。

反馈时分别标注四类缺口：事件边界不清、因果依赖断裂、资源所有者缺失、把实现选择或性能猜测写成普遍结论。只浏览页面或运行轨迹不产生通过判断。
