## Context

第 05 章交付了逐拍调度循环：六项合同定义可运行集合，准入按空闲块判定，策略只迁移等待。它的教学池从未真正见底，“等待块”只在一个实践场景里短暂出现。第 06 章把压力调到持续超过排水能力，让准入从循环的一项输入变成核心设计问题，见 `proposal.md` 与 `specs/overload-admission-chapter/spec.md`。

现有站点的持续约束继续有效：正文在隐藏图示与实践后仍须成立；确定性逻辑拍不能冒充真实耗时。本章会接触准入控制、水位、抢占与重计算等真实机制：机制名称在推导之后出现；vLLM 的抢占行为（默认 RECOMPUTE、抢占最低优先级）以锁定版本作实现示例，论文与文档的性能表述只登记为其自身条件下的结论。

## Goals / Non-Goals

**Goals:**

- 让一次突发把 6 块池打到见底，“等待块”从单请求状态变成队列常态；无界排队轨迹展示队列增长与先来后到的继承。
- 把准入重新表述为成本分配：排队把成本给等待者，拒绝给调用方，抢占给被抢占者；四条轨迹在同一工作量上给出四张不同的账单。
- 让水位成为可手算的旋钮（W=0 与 W=1 在同一时刻对大/小请求给出相反裁决），并让抢占重计算回到第 03 章的无缓存重算路径。
- 以计数对照收束：总拍数、被拒、被抢占、重计算 token、最大排队、首执行拍；没有免费方向，策略编码服务承诺。
- 把“等待中的请求被客户端放弃”登记为第 07 章引子。

**Non-Goals:**

- 不实现真实准入控制器、优先级队列、swap/offload 或分层 KV。
- 不把拍数、队列深度或重计算量换算为延迟、吞吐或公平性数值；真实结论需要测量。
- 不在本章给任何策略写推荐值或“最佳实践”。
- 不改动第 00—05 章已验收的内容、模型与数字。

## Decisions

### 1. 从“池见底”开始，而不是从准入机制开始

正文先让突发发生：`P-a`、`P-b` 同拍到达各占 2 块，`P-c` 在 t1 恰好用掉最后 2 块，`P-d` 在 t2 面对空池。第 05 章的循环此刻第一次答不出“这一拍执行谁”——不是因为没有候选，而是因为候选缺容量。无界排队是最小的默认：把 `P-d` 登记为等待块，每拍重试。轨迹显示等待成为常态、队列随到达增长，且先来后到被容量可行性打断（第 05 章实践已见过一次）。问题随之改写：过载的成本已经发生，唯一的选择是让谁承担。

替代方案是先介绍准入控制器再演示。它更快给出术语，但学习者无法回答“拒绝/排队/抢占分别把成本转嫁给了谁”，因此不采用。

### 2. 四条确定性轨迹，共用同一工作量与块池

工作量固定为 `P-a`/`P-b`（t0 到达，5+3）、`P-c`（t1，5+3）、`P-d`（t2，3+2），池 6 块 × 4 unit，拍内顺序沿用第 05 章（prefill 优先）。四条手算结局：

- **无界排队**：7 拍完成，无人被拒或被抢占，`P-d` 首执行 t5，最大排队 1。
- **按满拒绝（W=0）**：`P-c` 因恰好有 2 块空位被准入，`P-d` 在 t2 被立即拒绝；5 拍完成三个请求。
- **水位拒绝（W=1）**：同一时刻 `P-c`（需 2 块，剩余 0 < 1）被拒、`P-d`（需 1 块，剩余 1 ≥ 1）被准入；同样 5 拍，裁决方向相反——水位保护在跑者的余量并偏好小申请。
- **抢占重计算**：`P-d` 到达时抢占最近开始生成的 `P-b`，归还其 2 块；`P-d` 当拍准入、t3 首执行并 t4 完成，`P-b` 以重计算恢复——重新 prefill 其 prompt 加已生成 token（6 个 token 的重复工作）。总拍数与排队相同（7 拍）：抢占买到的是晚到者的提前入场，代价是 6 unit 重计算，且在跑者全部从 t4 推迟到 t6 完成。

抢占规则取“最近开始生成者”并显式登记为教学假设；真实系统按优先级与到达时间选受害者（版本锁定示例）。重计算恢复写明这是第 03 章“无缓存重算”的回归：缓存丢掉后，语义不变，成本是重新计算。

### 3. 一套领域模型生成四条轨迹与成本账单

新增 `src/learning/overloadTrace.ts`：

- `OverloadPolicy = 'queue' | 'reject' | 'preempt-recompute'`，`watermarkBlocks` 参数（默认 0）。
- `OverloadEvent`：到达、准入、排队（等待块）、拒绝（记录 free/need/watermark）、抢占（受害者、归还块、已生成 token）、重计算 prefill（token 数）、prefill/decode 执行、完成、块释放与获取。
- `OverloadTickSnapshot`：空闲块、排队深度、每请求状态（含“排队重计算”）。
- `overloadSummary(trace)`：总拍数、被拒、被抢占、重计算 token、最大排队、每请求首执行/完成拍——正文、图与实践消费同一结果。
- 校验器：块数不越界、抢占只发生在空闲不足且受害者持有块时、重计算 prefill 的 token 数等于 prompt 加被抢占时已生成数、每请求恰一次终结、水位裁决与 free/need/W 一致。

### 4. 连续正文只在五次认知任务变化时分段

1. **突发让池见底**：等待成为常态；无界排队轨迹；队列增长与继承。
2. **过载成本必有承担者**：问题重述；按满拒绝与水位拒绝两条轨迹；W 作为旋钮的相反裁决。
3. **抢占：请一位在跑者让位**：抢占轨迹；受害者选取；重计算恢复与第 03 章的呼应；真实 swap 作为命名替代（不建模）。
4. **优先级把排队变成有向选择**：优先级是第二个旋钮（谁先出队、谁先被抢占）；真实框架按优先级抢占（版本锁定）；本章只做定性讨论与一次手算变体。
5. **没有免费方向，只有服务承诺**：四张账单对照；策略编码承诺（快速失败/尽量服务/保护在跑者）；真实吞吐、尾延迟与公平性需要测量；等待者被客户端放弃持有无效希望，留给第 07 章。

分节标题只对应认知任务变化；不设“原理”“工程视角”“优缺点”“小结”。

### 5. 两张图分别回答轨迹演化与成本对照

第一张“过载时的池与队伍”图：逐拍双条带（空闲块数、排队深度）加事件账本，策略与水位可切换，重计算事件显式标注。第二张“四种策略，四张账单”图：策略为行、成本计数为列的对照账本，每行高亮成本承担者（等待者/调用方/被抢占者），数字来自 `overloadSummary`。两图沿用暂停、前后单步、重置、键盘、reduced-motion、窄屏内部滚动与文字/图案双编码。

替代方案是可调水位与到达率的通用模拟器；它会把分配问题降格为参数试玩并暗示存在最优旋钮，因此不采用。

### 6. 实践经过 prose-only 评审，迁移验收固定存在

候选实践提供一份未解释的过载账本（新突发工作量与更小池，含真实的拒绝或抢占事件），学习者先判断首个被拒/被抢占请求的成本由谁承担，再重建一次准入裁决的完整顺序（到达 → 计算 free/need/W 或抢占裁决 → 准入/排队/拒绝/抢占 → 登记 → 执行）。迁移评估换用不同的水位、突发与池规模，先检查一个致命归因错误（如把排队当调度不公平、把重计算当免费），再覆盖决定点、承担者归因、抢占与重计算顺序、水位权衡、证据边界与待解问题六个维度。不自动评分、不写持久状态、不以背诵术语为完成证据。

## Risks / Trade-offs

- **四条轨迹过重** → 工作量刻意小（4 请求、5—7 拍），每条轨迹的完整事件表不超过 25 行，手算可复核；正文表格只呈现差异行。
- **抢占写成“正确答案”** → 抢占与排队总拍数相同（7 拍）且引入重计算成本、在跑者完成拍推迟；账单对照不给推荐，真实框架的选择以版本锁定示例呈现。
- **重计算与第 03 章概念冲突** → 显式回指“无缓存重算路径回归为恢复机制”，语义不变、成本重现，形成主线闭环而非新概念。
- **优先级讨论滑向策略设计** → 优先级只作定性旋钮与一次手算变体；公平性度量登记为测量问题。
- **计数被误读为延迟** → 每张对照表旁固定证据边界语句；出现“延迟/吞吐”字样处一律指向测量。
