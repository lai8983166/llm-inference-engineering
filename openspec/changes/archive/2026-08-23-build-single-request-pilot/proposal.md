## Why

课程需要先证明“连续推导为主、实践按需出现”的教学方法能够真正讲清一个主题，而不是立即铺开全部章节。第 01 章覆盖模型语义、请求状态与工程边界，适合作为检验正文深度、信息密度和实践必要性的首个样板。

## What Changes

- 建立适用于后续章节的教学契约，约束标题密度、正文连续性、概念引入顺序和重复表达。
- 完成第 01 章“一次请求怎样活着”的内容与学习路径设计，从 API 请求逐步推导到自回归循环、prefill、decode、sampling、streaming 和终止语义。
- 将请求状态、资源生命周期、取消和清理作为工程设计的一部分自然接入理论推导。
- 只在可执行状态演化能够提供额外认识时保留一个小型实践；不为每个小节配置 Lab。
- 为正文、工程分析和可选实践定义不同的验收证据，防止用页面访问或运行成功代替理解。

## Capabilities

### New Capabilities

- `narrative-teaching-contract`: 规定章节如何以认知演进组织正文、控制标题和辅助元素，并按学习目标决定是否需要实践。
- `single-request-pilot`: 规定第 01 章的知识范围、连续推导、工程落点、必要实践和学习验收。

### Modified Capabilities

无。

## Impact

本次变更将建立首个可审阅的课程章节及其最小承载结构，并形成后续章节复用的内容约束。范围不包含第 02 章以后正文、完整推理引擎、真实 GPU 性能实验、vLLM/SGLang 源码修改或全站功能建设。
