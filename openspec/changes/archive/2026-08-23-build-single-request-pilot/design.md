## Context

项目当前只有课程蓝图和 OpenSpec 配置，还没有内容承载层。首个样板既要建立最小可阅读页面，也要验证 README 中的教学原则能否落实；如果一开始引入复杂课程平台、进度系统或大量交互，结构本身会掩盖正文质量。

## Goals / Non-Goals

**Goals:**

- 让第 01 章在没有实践组件时仍是一篇完整、连续、可独立理解的教程。
- 建立可复用但不过度模板化的内容契约和人工审阅标准。
- 用一个最小状态轨迹实践检验“实践只提供额外认识”的边界。
- 为后续 GPU、KV 和调度章节留下稳定的请求事件与资源术语。

**Non-Goals:**

- 不建设账号、跨设备进度、课程编辑后台或完整组件库。
- 不实现多请求调度、真实模型推理、KV allocator 或 GPU benchmark。
- 不在样板章展开 vLLM、SGLang 的版本化源码细节。

## Decisions

### 正文使用 prose-first 内容源

章节正文采用 Markdown/MDX 一类以段落为第一等结构的内容源，页面组件只负责排版、必要图示和明确的实践插入点。不会沿用把每段内容拆成卡片对象的注册表模式，因为它会诱导编辑者用 UI block 代替过渡句。

备选方案是直接将正文写成 React 组件；它减少构建插件，却使长文编辑、结构审查和内容差异变得困难。首期仍采用 React、TypeScript 与 Vite 作为最小承载层，以复用相邻项目已经验证的开发方式，但不复制其课程卡片结构。

### 一章只保留一条可见主线

第 01 章按五次实质认知转折展开：一次 API 调用为何是长期过程；同一循环为何形成 prefill 与 decode；生成决策为何不等于模型计算；streaming 如何改变可见边界；终止路径如何暴露资源所有权。标题只标记这些转折，术语定义、工程说明和思考问题嵌入相邻正文，不再各自建立重复标题。

备选方案是按 tokenizer、prefill、decode、sampling、streaming 分成并列知识卡片。该结构便于检索，却隐藏了前后因果，因此不采用。

### 使用一个贯穿算例而非多个演示场景

正文使用同一请求贯穿 token 化、prefill、逐 token decode、采样、流式输出和终止。中途只改变一个条件——正常完成或 decode 期间取消——使新概念消费前面已经建立的状态。

算例同时保留事件、状态、可见输出与资源四条记录，但页面默认随正文逐步展示，不一次呈现大型总表。最终汇总用于复查，不再次复述段落结论。

### 工程设计通过状态与所有权自然接入

正文先从模型依赖推出必须跨步保存的请求状态，再讨论最小执行循环、状态转换和资源清理。工程内容不使用固定“工程放大镜”板块；只有风险或假设需要从主叙事中暂时分离时才使用旁注。

最小实现只承诺单请求语义正确，并主动暴露同步执行、无批处理、无设备并发和粗粒度取消等限制。这些限制作为第 02 章及后续章节的问题入口，不在本章提前解决。

### 状态轨迹实践在正文完成后单独验证

保留一个确定性、无计时动画的状态轨迹实践，原因是“取消信号与生成/发送事件相邻发生”涉及动态顺序和幂等清理，仅靠阅读容易隐藏错误直觉。学习者先预测终态和资源归属，再逐事件核对；实践不教授新术语，不以运行完成计为掌握。

如果正文评审发现该实践没有产生新的可观察证据，将删除实践并改为静态事件审查题。是否保留由认识增量决定，而不是由计划中已经出现 `Lab` 字样决定。

### 自动检查只守住结构底线

自动测试覆盖路由、标题唯一性、语义层级、必要内容锚点、状态转换和资源释放不变量。标题是否重复表达、段落是否像幻灯片、过渡是否自然必须由人工连续阅读审查，不能用字数或卡片数量伪装成质量指标。

桌面与移动端都使用单列阅读主区；导航、目录和状态摘要不得同时占据主要视野。首期不记录浏览进度，只保存实践中的显式预测或结果；清除本地状态后不保留掌握结论。

### 动态图跟随认知变化而不是装饰页面

prose-first 不等于 text-only。样板章在四个正文已经建立问题的位置插入可操作示意：首屏先展示一次请求包含多个内部时刻；prefill/decode 推导后切换因果矩阵与执行形状；streaming 推导后逐步移动模型、请求、客户端和资源四条时间线；所有权推导后观察终止许可关闭与资源安全释放的先后。

图示 MUST 使用正文已经解释的符号，并允许暂停、单步或直接选择状态。自动运动只用于提示系统仍在推进，不能承载只有等待动画才能获得的结论；`prefers-reduced-motion` 下停止非必要运动。图示是正文中的推理证据，不把每个段落包装成卡片，也不复刻相邻项目的页面结构。

## Risks / Trade-offs

- [长文缺少足够导航] → 只为五个认知转折设置锚点，并通过顶部简短目录验证能否快速返回，不在正文重复阶段标签。
- [MDX 让内容与组件边界复杂] → 首期只允许少量显式组件，普通概念、公式和代码保持标准 Markdown 表达。
- [贯穿算例过于理想化] → 在取消与失败处引入反例，并明确单请求模型尚不能说明多请求调度和真实性能。
- [实践再次喧宾夺主] → 先完成并评审无实践版本，再实现轨迹组件；若移除组件不损失动态认识，则不交付该组件。
- [过早固化后续章节模板] → 教学契约只规定认知和证据边界，不规定每章标题数量、页面模块或 Lab 数量；样板评审后再决定复用范围。
- [动画吸引注意却没有增加理解] → 每张图只改变一个前文变量，并用可见状态读数和文字说明给出同等信息；不使用持续滚动、计时挑战或无法暂停的装饰运动。

## Migration Plan

先建立最小站点与 prose-first 内容契约，再完成无实践版本的第 01 章并进行连续阅读评审。正文通过后才添加状态轨迹实践和验收问题。最终根据样板评审更新教学契约；在评审完成前不复制到第 02 章以后。
