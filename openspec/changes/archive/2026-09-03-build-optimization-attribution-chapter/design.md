## Context

第 08 章交付了指标层与归因指向（首 token 正常而间隔劣化指向 decode 路径），并把"哪一层慢 → 哪一行慢"留给本章。第 09 章面对的是优化工作的核心风险：局部优化与端到端收益之间隔着预算占比、瓶颈指纹与测量噪声三道关口，见 `proposal.md` 与 `specs/optimization-attribution-chapter/spec.md`。

现有站点的持续约束继续有效：正文在隐藏图示与实践后仍须成立；教学数值不能冒充真实测量。本章引入**预算单位**（一个解码步的成本分解为五部件的整数教学单位）——与第 03 章 token unit 同构：算术可迁移，数值不可迁移，真实 profiling 必须实测。

## Goals / Non-Goals

**Goals:**

- 用预算表展示"局部变快两倍、服务快 5%"的算术：端到端 = 部件之和，收益由占比决定。
- 建立五种瓶颈指纹：Python/CPU 提交、launch 间隙、同步、访存带宽、计算——各自的特征观察与对应优化。
- Amdahl 上限 `1/(1−占比)` 由预算表手算复现；优化选择先查上限再动手。
- 噪声与对照：固定记录样本的范围重叠判定、最小对照实验纪律、观测者效应。
- 归因链收束：指标 → 层 → 指纹 → 假设 → 最小实验 → 确认，衔接深化分支与第 11 章真实框架。

**Non-Goals:**

- 不实现真实 profiler、kernel 优化或 CUDA Graph；不给出任何真实毫秒、GB/s、FLOPS 数值。
- 不建模流水线重叠（部件串行求和是登记的教学简化）；不展开 roofline 模型定量分析。
- 不比较真实框架优化选项的实际收益；实现示例只印证取舍存在。
- 不改动第 00—08 章已验收内容。

## Decisions

### 1. 从"kernel 减半、服务没动"的反例开始，而不是从 profiler 工具开始

正文第一幕是一个固定预算表的解码步：提交 2、launch 8、同步 2、访存 6、计算 2，合计 20 单位——launch 占 40%。一次"把计算 kernel 时间减半"的优秀优化把 20 变成 19：端到端快 5%。kernel 确实快了一倍，报告没撒谎，收益去哪了由算术回答。随后反转视角：同一预算表里把 launch 压到四分之一（如 CUDA Graph 一类的机制）得到 14 单位、快 1.43 倍——优化谁，由预算表决定，不由直觉决定。

替代方案是先介绍 profiler 工具分类。它更快进入操作，但学习者无法回答"为什么我优化的不是收益"，因此不采用。

### 2. 五部件预算与优化变换的确定性模型

新增 `src/learning/bottleneckLedger.ts`：

- `BottleneckKind = 'submit' | 'launch' | 'sync' | 'memory' | 'compute'`；`StepBudget` 为五部件整数单位。
- 固定基线 `baselineDecodeBudget = { submit: 2, launch: 8, sync: 2, memory: 6, compute: 2 }`（launch 主导，使反例鲜明）。
- `OptimizationSpec = { id, name, target, factor }`；`optimize(budget, spec)` 纯函数；`total(budget)` 求和。
- `speedup(before, after)` 与 `ceiling(budget, target)`（部件归零的上限 = `1/(1−占比)`，Amdahl 手算复现）。
- 固定优化表：更快 kernel（compute ×0.5 → 20/19）、CUDA Graph（launch ×0.25 → 20/14）、KV 量化（memory ×0.5 → 20/17）、去同步（sync ×0 → 20/18）；各配上限行。
- `noiseCases()`：两组固定记录样本——无实质变化（前 [18..22] 均值 20、后 [19..21] 均值 20，范围重叠）与真实收益（launch 优化后 [13..15]，范围分离）；`rangeOverlap` 布尔判定与"重叠不得声称、分离仍需同条件"的结论模板。

### 3. 连续正文只在五次认知任务变化时分段

1. **局部变快，端到端没动**：预算表反例；收益去哪了的算术。
2. **五种瓶颈，五种指纹**：各部件的观察特征（CPU 提交占比、launch 间隙、同步等待、带宽受限、计算受限）与对应优化；真实 profiler 的取舍与观测者效应以版本锁定示例呈现。
3. **预算表决定收益上限**：Amdahl `1/(1−占比)` 手算；优化前先查上限的纪律。
4. **噪声、对照与最小实验**：固定样本表；范围重叠不能声称；最小对照实验沿用第 00 章合同，分布口径沿用第 08 章。
5. **归因是证据链，不是直觉**：指标 → 层 → 指纹 → 假设 → 最小实验 → 确认或推翻；主线收束，交给深化分支与真实框架。

### 4. 两张图分别回答预算构成与归因链

第一张"收益去哪了"图：基线预算的堆叠条 + 优化选择切换后的新堆叠条与收益读数、上限对照；一图呈现多种优化的不同收益。第二张"噪声与对照"图：两组样本的取值条带与范围括号，重叠/分离判定与结论模板切换。两图沿用暂停无关的静态切换或单步、键盘、reduced-motion、窄屏内部滚动与文字/图案双编码。

### 5. 实践经过 prose-only 评审，迁移验收固定存在

候选实践提供一份未解释的优化报告（kernel 时间减半、样本范围重叠、端到端声称提升），学习者先判断收益为什么没兑现（占比、噪声或指纹错配），再重建归因链顺序。迁移评估换用新预算表与样本组合，先检查一个致命归因错误（如"kernel 快了服务必然快"或"范围重叠也算改进"），再覆盖预算、指纹、上限、噪声、证据边界与归因链六个维度。不自动评分、不写持久状态、不以背诵术语为完成证据。

## Risks / Trade-offs

- **预算单位被误读为真实毫秒** → 全文以"单位"表述并固定证据边界语句；真实 profiling 全部指向实测。
- **串行求和过度简化** → 正文登记为教学简化并说明重叠会让局部收益更难兑现，不建模。
- **Amdahl 被当成并行专属** → 正文明确它的一般形式：任何"部分优化"的上限都由占比决定。
- **噪声样本被当作真实数据** → 样本表标注为固定记录的教学样本；真实噪声必须现场测量。
- **数字漂移** → 预算、优化与样本全部由同一纯函数族给出，测试独立复算收益与上限。
