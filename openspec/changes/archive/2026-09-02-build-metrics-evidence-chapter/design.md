## Context

第 00 章建立了单请求层的测量合同（固定负载、观察者、原始事件、结论边界），第 05—07 章把服务层事件攒齐：到达、准入、排队、执行、带原因的终态。第 08 章在事件与结论之间补上指标层，见 `proposal.md` 与 `specs/metrics-evidence-chapter/spec.md`。

现有站点的持续约束继续有效：正文在隐藏图示与实践后仍须成立；确定性逻辑拍不能冒充真实耗时。本章是这条纪律的最终考场——它必须教指标，又必须不把拍换算成毫秒。解法是把指标定义为**事件对的差值**：定义可迁移（真实系统对时间戳做同样的差），数值不可迁移（教学单位是拍）。

## Goals / Non-Goals

**Goals:**

- 用事件对差值定义排队拍、首 token 拍（TTFT）、token 间隔（ITL）、端到端（E2E）：每个指标钉死起止事件，边界选择（从到达还是从准入起算）改变数值。
- 手算"均值更好但 SLO 更差"的反例：分布先于均值，SLO = 阈值 + 分位。
- 在同一服务上对照开放环（到达独立于服务）与闭环（完成后再发下一个）：闭环隐藏排队，两环测的不是同一件事。
- 用终态原因定义 goodput：拒绝、失败、被放弃的完成不进有效产出；吞吐与 goodput 分叉手算可复核。
- 把聚合链建立为可回溯证据：原始事件 → 每请求指标 → 分布 → SLO 判定，任何分位能指回请求。

**Non-Goals:**

- 不实现真实压测器、Poisson 采样器或统计库；分位数用小样本手算定义（最近邻秩），不引入插值争议。
- 不把拍换算为毫秒或任何真实时间量纲；不声称教学分布代表真实负载。
- 不比较真实系统的指标数值；实现示例只用于印证定义与口径选择真实存在。
- 不改动第 00—07 章已验收内容。

## Decisions

### 1. 指标是事件对的差，定义先于数值

正文从一个含糊的问题开始："这个服务快不快？"八章的答案一直是"先给事件"；现在事件有了，新的含糊在定义——首 token 从到达算还是从准入算，差出整整一段排队。由此钉死四组事件对：排队 = `admitted − arrived`；首 token = 首个输出事件 − `arrived`；间隔 = 相邻输出事件之差；端到端 = 终态事件 − `arrived`。每个定义配一个"换边界就换数值"的小反例。真实工具同样要钉边界——版本锁定的压测文档把客户端并发等待（`client_queue_time`）单列为独立指标，正是同一课。

替代方案是直接给出指标名词表。它更快，但学习者无法回答"为什么两个报告的 TTFT 对不上"，因此不采用。

### 2. 教学工作量与指标层纯函数

新增 `src/learning/metricsLayer.ts`，事件底座复用 `buildOverloadTrace`（它已含到达/准入/排队/执行/完成/拒绝/抢占与拍数）：

- 固定工作量约 6 个请求、6 块池、水位拒绝 W=1：包含被拒者（goodput 分叉）、长短混合（ITL 分布有形状）、串行到达（排队拍非零）。
- `requestMetrics(trace)`：每请求的排队拍、首 token 拍、间隔数组、端到端拍与终态原因，全部由事件差推导。
- `distribution(values)` 与 `percentile(values, p)`：排序、均值、p50/p99/max；分位用最近邻秩定义并显式登记。
- `sloVerdict(values, threshold, percentile)`：阈值加分位的判定。
- `goodputSummary(trace)`：吞吐（完成数/窗口）与 goodput（有效完成数/窗口）并列，无效完成按终态原因列出。
- 手算反例 `meanTailCounterexample()`：两组间隔分布，A 均值更好、B 尾部与 SLO 判定更好；若第 05 章双策略在同一工作量上的间隔分布恰好呈现分叉则用真实轨迹，否则用登记的教学分布。

### 3. 开环与闭环是负载生成器的性质，不是服务的性质

同一服务、同一请求集合，两种到达过程：**开放环**（到达时刻预先固定，与服务状态无关——本课程全部 fixture 都是开环）与**闭环**（客户端等上一个请求完成再发下一个）。闭环下排队被客户端的串行节奏吸收——队列深度恒小、等待近乎为零，测出的是"无排队服务能力"，不是"过载下的行为"。教学模型用纯函数生成闭环到达表（下一请求到达 = 上一请求终态拍 + 1），与开环表并列跑同一服务，对照队列深度与各指标。真实压测工具的 `--request-rate=inf`（全部立即到达）与有限速率 Poisson 到达、以及 `--max-concurrency` 限制在途并单列客户端排队指标，是同一组选择的版本锁定示例。

### 4. 连续正文只在五次认知任务变化时分段

1. **每个指标都是事件对的差**：从"快不快"到四组钉死的定义；边界选择反例。
2. **分布先于均值**：均值隐藏尾部；A/B 反例手算表；SLO = 阈值 + 分位；报告必须带分布。
3. **开放环与闭环测的不是同一件事**：两环对照；闭环隐藏排队；真实工具的速率与并发参数。
4. **完成不等于有效**：goodput 用终态原因剔除拒绝、失败与被放弃；吞吐与 goodput 分叉表。
5. **聚合链要能走回头路**：原始事件 → 每请求 → 分布 → 判定，每步可回溯；报告模板；指标异常指向哪一层（排队/prefill/decode/终止），交给第 09 章。

### 5. 两张图分别回答链路与环式

第一张"从事件到分布"图：上半是单个请求的事件尺（可切换请求），下半是该指标全体取值的排序条带，均值/p50/p99 标记与 SLO 线并列，A/B 系统切换呈现反例。第二张"开环与闭环"图：同一服务的两条时间线并排，到达标记与队列深度条带对照，读数给出两环的排队与首 token 差异。两图沿用暂停、前后单步、重置、键盘、reduced-motion、窄屏内部滚动与文字/图案双编码。

### 6. 实践经过 prose-only 评审，迁移验收固定存在

候选实践提供一份未解释的指标报告与配套原始事件（新工作量），学习者先找出报告里的定义错误（如首 token 从准入起算把排队藏进指标、只报均值不报分布），再重建聚合链顺序。迁移评估换用闭环负载与含拒绝/失败的工作量，先检查一个致命口径错误（如闭环宣称"零排队所以不会过载"、吞吐当 goodput），再覆盖定义、分布、环式、口径、证据边界与归因指向六个维度。不自动评分、不写持久状态、不以背诵指标名词为完成证据。

## Risks / Trade-offs

- **教指标又违反拍纪律** → 每个指标显式标注"事件对差值，单位为拍"；出现"毫秒/秒"字样处一律指向"真实系统对时间戳做同样的差"。
- **分位数定义争议** → 小样本用最近邻秩并在正文登记；不引入插值，避免统计细节淹没主线。
- **反例被读成"均值无用"** → 正文明确均值回答总量问题、分位回答承诺问题，两者服务不同决策。
- **闭环演示滑向排队论** → 只做"串行客户端"一种闭环并说明真实并发由参数控制；不展开排队论。
- **数字漂移** → 全部指标由同一事件族推导，测试从原始事件独立复算关键分位与 goodput。
