## Context

第 03 章已经建立 KV cache 的语义、128 bytes/token 的字节账本、请求级所有权，并让最大预留与按需连续增长在同一 24 token unit 池上分别暴露过度预留、搬迁双份存活与外部碎片，见 `proposal.md` 与 `specs/paged-kv-chapter/spec.md`。第 04 章接住它留下的问题与四条布局合同，推导出离散布局的真实形态。

现有站点使用 MDX 承载连续正文，React/TypeScript 组件只呈现文字难以观察的状态。第 00—03 章形成了持续约束：正文在隐藏图示与实践后仍须成立；图示不能用装饰动画替代因果解释；确定性逻辑步和教学内存池不能冒充真实 GPU 耗时、显存布局或框架性能。

本章会接触 block pool、block table 与 paged attention 等真实机制。稳定原理（固定粒度分配为何消除外部碎片、间接层为何以元数据为代价）回到操作系统分页的教科书事实与 PagedAttention 论文的显式声明；vLLM/SGLang 当前实现细节必须锁定版本并只作实现示例，不充当概念定义。

## Goals / Non-Goals

**Goals:**

- 用第 03 章四条合同逐一裁决候选布局：压缩为何只是修补、离散分段为何保住语义并消除被迫搬迁、变长分段为何让碎片在分段粒度重生。
- 让固定块由“任何空位可服务任何增长”推导出来，并让块表作为显式映射合同出现，其元数据进入可计数账本。
- 用同一物理池、同一请求工作量生成块池轨迹，并与第 03 章连续轨迹对照：块内追加、整块回收、空块复用、零搬迁。
- 把块大小写成“内部浪费 ↔ 映射规模”的显式交换，用 B=1、2、4、8、24 手算对照，不越界到真实查找成本。
- 只保留能增加映射与池演化可观察性的图示与实践，并以新配置迁移诊断验收。

**Non-Goals:**

- 不实现真实 block allocator、paged attention kernel、block-size 自动选择或并发安全分配器。
- 不把教学块、块表或逻辑步映射为 CUDA 地址、真实分配粒度、毫秒、带宽或 GPU 利用率。
- 不在本章引入 prefix sharing、copy-on-write、抢占、分层 KV 或调度策略，只把它们登记为块池之后仍未解决的问题。
- 不把 vLLM/SGLang 的具体数据结构当作本章推导的出发点或终点答案。

## Decisions

### 1. 从四条合同裁决候选布局，而不是从数据结构介绍开始

正文先复述第 03 章合同：逻辑位置到存储位置的映射、每步末尾追加一个位置、在途读取依赖权威状态、请求独立的终结与回收。任何候选布局只用两条标准裁决：合同是否全部保住、容量行为是否改善。

压缩方案先用一小段收束：它保住合同，却以反复复制、在途协调和搬迁峰值为代价，是事后修补而非解除“必须连续”的约束。随后提出最小放松：允许一个请求的 KV 由多段构成。逐条检查合同后确认语义不变——Attention 读的还是同一批位置的字节，代价只是“读取必须先经过映射”。于是“映射是什么”成为下一问，而不是框架赠品。

替代方案是开篇直接介绍 block pool 结构。它更快进入实现，但学习者无法回答为什么块是定长、表为什么必须存在、浪费去了哪里，因此不采用。

### 2. 固定块由复用粒度推导，教学参数延续第 03 章

变长分段是离散化的第一直觉：把每段切得刚好放进空位。正文用一张手算表显示空位匹配重新引入尺寸专属——碎片在分段粒度上重生，只是换了一层。由此推导固定块：若每段都是 B 个 unit，任何空闲块可服务任何请求的下一次增长，匹配问题消失；代价转为内部浪费，且每个请求被 B−1 封顶。

教学参数延续第 03 章：模型仍为 4 层、8 query heads、2 KV heads、head dim 4、2 bytes/element（128 bytes/token）；物理池仍 24 token unit，划分为 4-unit 块共 6 块；请求仍为 `R-long`（6+4）、`R-short`（2+1）、`R-late`（4+2）。完成态恰好 3/1/2 个块，块内浪费 2/1/2 unit。关键事件序列可手算：`R-short` 在 step 1 结束归还块 B2，`R-long` 在 step 2 的新块恰好复用 B2；`R-long` 的第 8、10 个 token 只是块内追加，不发生任何分配。

替代方案是换更大的池或更多请求让块池更“像生产”。那会淹没 6 块池里每个事件的可复核性，因此先用手算 fixture，迁移评估再换参数。

### 3. 一套领域模型同时提供块池轨迹与连续基线对照

第 03 章 `kvStateTrace` 的连续按需轨迹直接复用为基线，不重写。新增块池数据边界：

- `BlockPoolFixture`：块大小（token unit）与块数。
- `BlockLease`：块编号、所有者、已用 unit 与世代。
- `BlockTableSnapshot`：请求 phase、逻辑 token 数、表项（块编号序列）、持有块数、内部浪费 unit、在途读取与释放许可。
- `BlockPoolEvent`：到达、分配块、块内追加、表项登记、读取完成、整块释放、拒绝及其逻辑步。
- `BlockPoolSnapshot`：按块编号排序的块状态、空闲块数、内部浪费合计与“当前可满足的最大 token 数”。

纯函数负责生成块池轨迹、按任意 B 重算表项与浪费计数，以及对照连续轨迹输出“迁移次数、拒绝、最终空闲”差异。正文表格、图与实践消费同一结果。字段名与辅助文本禁止出现 `ms`、`GB/s`、`utilization`，不得把块编号声称为真实显存块地址。

### 4. 连续正文只在五次认知任务变化时分段

1. **拆成几段，合同还在吗**：复述四条合同，压缩收束，最小放松到分段存储；迁移从“被迫”变成“不存在”，映射成为新问题。
2. **空位复用卡在粒度上**：变长分段让空位匹配重生碎片，推导固定块；**块**在矛盾之后命名，内部浪费被封顶。
3. **块表是显式的映射合同**：逻辑位置 → 表项 + 块内偏移；追加、读取与错误后果（错表项=读错 K/V=正确性缺陷）；**块表**命名，元数据进入账本。
4. **块池准入与独立回收**：按空闲块准入、整块归还、取消只动自己的块；同一三请求在同一池上的块池轨迹，与第 03 章 step 1 外部碎片场景对照得到第三种结局。
5. **块大小把浪费换成间接**：B 的两个极端退化为逐 token 映射与第 03 章连续情形；B=1、2、4、8、24 手算表项数与浪费 unit；真实查找与 kernel 成本是测量问题；收束到块池仍未解决的准入、共享与访问模式问题。

分页、块、块表等名称只在相应矛盾出现后解释。公式、手算表和对照嵌在段落中，不另设“原理”“工程视角”“优缺点”“小结”标题。

### 5. 两张图分别回答映射翻译与池演化对照

第一张“块表怎样翻译一次读取”图沿一次 decode 展示逻辑位置带 → 块表 → 散布物理块的翻译路径，允许在“连续区间（无表直读）”与“块表（逐项翻译）”之间切换；两条路径读取同一批位置，差异只在翻译步骤数，界面不声称速度差异。

第二张“同一池的第三种结局”图以块对齐地址带与事件账本展示块池轨迹，允许切换到第 03 章连续按需轨迹；同一池、同一请求，迁移事件消失，空块被复用。两图共享既有交互约束：暂停、前后单步、重置、键盘、reduced-motion 初始暂停、窄屏内部滚动、文字/图案双编码。

替代方案是可调块大小的通用模拟器。它会把推导降格为参数试玩并暗示存在最优 B，因此不采用；块大小对照交给正文手算表与迁移评估。

### 6. 实践仍需经过 prose-only 评审，迁移验收固定存在

候选实践提供一段未解释的块池事件（新请求工作量与新池），学习者先判断首个失败或首个复用事件说明什么，再重建一次合法的“分配块 → 表项登记 → 块内追加 → 整块释放”顺序或一次逻辑位置到物理块的翻译。只有它要求主动组合映射、粒度与所有权时才保留。

章末迁移评估换用不同的块大小、模型维度、请求长度与池规模，先检查一个致命账本或映射错误（例如漏算表元数据、把内部浪费当作外部碎片），再以自由文本和展开标准覆盖分段语义、固定块推导、块表翻译、池准入与回收、证据边界与待解问题。不自动评分、不写持久状态、不以背诵术语为完成证据。

## Risks / Trade-offs

- **标题已含“分页”，推导被当成走形式** → 正文严格先矛盾后命名；`块`、`块表`、`分页`的首现位置由内容测试锁定在第 03 章矛盾复述之后。
- **把块池写成 vLLM 教程** → 真实实现仅以锁定版本的文档/论文作实现示例；概念定义回到分页原理与论文声明。
- **间接成本被忽略或被夸大** → 表项数与浪费 unit 全部手算可复核；真实查找耗时只作为测量问题登记。
- **块大小讨论滑向“最优 B”** → 对照表只数表项与浪费两个量纲，并明确真实选择需要测量与工作负载；不给出推荐值。
- **对照数字漂移** → 连续基线直接复用 `buildKvTrace('on-demand-growth')`，块池轨迹与对照差异由同一纯函数族生成，测试从原始参数独立复算。
- **章节膨胀进调度与共享** → 它们只登记为未解问题；任何调度策略、引用计数或 copy-on-write 数据结构留给后续章节。
