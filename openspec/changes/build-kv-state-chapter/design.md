## Context

第 01 章已经说明 decode 会反复读取历史状态，第 02 章已经把请求的可运行状态、phase、在途工作与资源所有权带入多请求执行。第 03 章需要把其中尚未展开的 KV 使用权变成可计算、可追踪的系统状态，见 `proposal.md` 与 `specs/kv-state-chapter/spec.md`。

现有站点使用 MDX 承载连续正文，React/TypeScript 组件只呈现文字难以观察的状态。前 00—02 章形成了持续约束：正文在隐藏图示与实践后仍须成立；图示不能用装饰动画替代因果解释；确定性逻辑步和教学内存池不能冒充真实 GPU 耗时、显存布局或框架性能。

本章会接触 Attention、GQA、dtype 与 KV 布局，但不把任何 vLLM/SGLang 当前数据结构当作概念定义。稳定公式和张量语义要回到论文、模型配置定义或一手文档；框架布局事实若出现必须锁定版本；峰值、带宽、复制成本与 OOM 行为只能由对应软硬件上的测量支持。

## Goals / Non-Goals

**Goals:**

- 用一次 decode 的历史依赖说明为什么 K/V 成为跨执行步状态，并明确缓存复用的正确性合同。
- 建立能从模型维度逐项复算的 KV 字节账本，区分有效 KV、保留未用、搬迁峰值、空闲区间和 allocator 元数据。
- 用同一组请求与同一物理池依次审查最大预留和按需连续扩容，让两种方案的合理性与失败都由事件产生。
- 把逻辑 token 顺序、物理地址发布、在途读取和释放许可建成独立状态，为下一章的布局解耦留下完整约束。
- 只保留能增加张量依赖或内存演化可观察性的图示与实践，并以新配置迁移诊断验收。

**Non-Goals:**

- 不实现真实 Attention kernel、paged attention、block pool、block table、prefix sharing、offload 或生产 allocator。
- 不把教学池的地址单位映射为 CUDA 虚拟地址、真实分配粒度、毫秒、带宽或 GPU 利用率。
- 不在本章比较 MHA/GQA/MQA 的真实速度或精度，也不展开训练态 K/V、反向传播和模型权重显存。
- 不提前决定第 04 章的 block size、引用计数、copy-on-write、回收或调度策略。

## Decisions

### 1. 先由无缓存重算形成 KV cache，而不是先展示显存公式

正文从第 01 章已经生成若干 token 的同一请求继续：第 n+1 个 token 的 query 需要与 0…n 的 key/value 发生 Attention。先完整列出“重算全部历史 token 的 K/V”和“读取历史 K/V、只追加当前位置”两条语义等价路径，再命名 KV cache。

推导只保留本章必要的张量边界：当前 query 是本步输入；历史与当前 key/value 构成跨步状态；attention scores、context 和 logits 在本步消费。位置编码、mask 和数值表示作为缓存键的一部分解释，但不扩张为 Attention 数学复习章。

替代方案是从“KV cache 能加速推理”的结论和显存公式开始。它能更快进入容量计算，却无法回答为什么只保存 K/V、缓存何时失效或错误复用为何改变结果，因此不采用。

### 2. 固定一个可手算模型，再沿尺度阶梯建立账本

教学模型固定为 4 层、8 个 query heads、2 个 KV heads、head dimension 4、每元素 2 bytes。由此每 token KV 为：

`4 layers × 2(K,V) × 2 KV heads × 4 dim × 2 bytes = 128 bytes`。

继续沿用第 02 章请求身份与工作量：`R-long` 为 6 prompt + 4 output，`R-short` 为 2 + 1，`R-late` 为 4 + 2。它们完成时的有效 KV 分别是 10、3、6 个 token unit，也就是 1280、384、768 bytes。页面同时保留原始维度、token unit 和字节结果，禁止只显示最终常数。

`queryHeads=8` 与 `kvHeads=2` 故意形成 GQA 反例，避免学习者把 query head 数误代入缓存公式。真实模型映射只作为后续核对示例，不让学习者在本章自由调出无法解释的大量组合。

替代方案是直接采用某个 7B/70B 模型并显示 GiB。数字更像生产环境，却会让参数规模掩盖 K/V 两份状态、KV heads 与 dtype 等因子，也容易受模型版本变化影响，因此先用可手算 fixture，再在迁移评估换配置。

### 3. 用一套领域模型驱动正文算例、图示和验收检查

最小数据边界包括：

- `KvModelFixture`：层数、query/KV heads、head dimension 与 dtype bytes。
- `KvRequestFixture`：请求标识、到达步、prompt/output token、最大上下文上限与终止原因。
- `KvAllocation`：物理起点、容量 token unit、已用 token、世代和所有者。
- `KvRequestSnapshot`：phase、逻辑长度、有效字节、保留字节、当前地址、在途读取数与释放许可。
- `KvMemoryEvent`：到达、预留、追加、原地增长、迁移开始、复制完成、地址发布、读取完成、释放、拒绝及其逻辑步。
- `KvPoolSnapshot`：按地址排序的有效、预留、迁移副本与空闲区间，以及总量和最大连续空闲区间。

纯函数负责计算每 token/请求字节、生成最大预留轨迹、生成按需连续增长轨迹，以及根据原始区间判断 `effective-capacity`、`over-reservation`、`migration-peak` 或 `external-fragmentation`。正文中的表、图和实践必须消费同一结果，不能各自维护一套数字。

事件模型中的地址和逻辑步都是整数教学单位。字段名、辅助文本和测试禁止出现 `ms`、`GB/s`、`utilization` 或把逻辑地址声称为 CUDA 分配结果。

### 4. 连续正文只在五次认知任务变化时分段

正文保持一条问题链：

1. **下一 token 又要过去的什么**：从无缓存重算引出跨步保存 K/V，并建立正确性边界。
2. **保存 K/V 不是免费的**：从 128 bytes/token 的手算阶梯进入三请求增长和所有权。
3. **最大预留把未知变成空占**：先承认稳定地址与简单准入，再用上限和实际长度差异暴露保留浪费。
4. **按需增长把空间变成搬迁**：从节省预留进入原地扩展失败、双份存活、地址发布和在途读取。
5. **空闲总量够，连续空间仍不够**：用请求独立结束后的孔洞区分总空闲与最大连续区间，形成逻辑连续是否需要物理连续的问题。

KV cache、capacity、reservation、relocation、external fragmentation 等名称只在相应矛盾出现后解释。公式、伪代码、区间表和工程合同嵌在这些段落中，不另设“原理”“工程视角”“优缺点”“小结”标题。

替代方案是按 Attention、公式、allocator、碎片分别建立知识卡。它便于局部检索，却会切断“为什么保存—保存多少—如何增长—为什么放不下”的因果链，因此不采用。

### 5. 最大预留与连续扩容共享同一物理池反例

教学池按 24 个 token unit 编址，每 unit 等于固定 fixture 的 128 bytes。最大预留方案为请求保留其声明上限，展示稳定地址如何以未用区间消耗准入容量；按需连续方案只给当前长度容量并允许小幅增长，随后让相邻请求和独立结束制造孔洞。

扩容事件严格分为：申请新区间、旧新区间同时存活、复制完成、发布新地址、等待旧地址在途读取归零、释放旧区间。任一步失败都保留旧地址为权威状态；取消只改变该请求的增长与释放流程，不得回收仍被读取的区间。

“总空闲足够但最大连续区间不足”只证明这套连续申请规则下发生外部碎片。正文分别讨论压缩、提前大块预留、拒绝增长等候选动作会改变的复制、同步或容量合同，但不把它们写成最终方案。

替代方案是直接画分页后的离散 block 如何装入空洞。它会在连续布局的失败尚未形成前泄露答案，并把下一章降格为机制说明，因此不采用。

### 6. 两张图分别回答依赖与物理演化，不做综合 allocator 模拟器

第一张“历史为何仍被读取”图沿一次 decode 展示当前 query 对历史 K/V 的读取、当前位置 K/V 的追加，以及不需要跨步保留的中间量。它允许暂停、前后单步和在“重算历史/复用历史”之间切换，但不显示虚构耗时收益。

第二张“连续区间怎样被逼到搬迁”图以地址带和事件账本同步展示三个请求的已用/保留空间、空闲孔洞、迁移双份存活、地址发布与旧区间等待释放。它允许在最大预留与按需连续增长之间切换，但使用同一物理池和请求工作量。

两图均保留文字/图案编码、当前事件、原始数值、暂停、单步、重置、键盘和 reduced-motion；窄屏让内部地址带横向滚动，不裁切章节正文或控制标题。

替代方案是可调池大小、增长倍率、请求长度和分配算法的通用模拟器。它会把本章变成参数试玩，并暗示存在无需推导的最佳 allocator，因此不采用。

### 7. 实践仍需经过 prose-only 评审，迁移验收固定存在

先完成完整正文、手算账本和两张解释图，再隐藏所有交互执行 prose-only 评审。候选实践只提供一段未解释的内存事件，让学习者先判断首个失败属于有效容量、过度预留、迁移峰值还是外部碎片，再重建合法的地址发布/释放顺序。只有这种主动重建提供了两张图无法替代的认识才保留。

章末迁移评估换用不同的层数、KV heads、dtype、请求长度与区间布局，先检查一个致命账本或所有权错误，再以自由文本和展开标准覆盖依赖语义、字节计算、容量归因、搬迁/释放顺序、证据边界与待解布局。页面不自动评分自由文本、不写持久学习状态，也不询问分页术语。

## Risks / Trade-offs

- **Attention 基础过多，主线迟迟进不了系统状态** → 只补齐 K/V 跨步依赖与缓存正确性所需的最小张量边界，把完整 Attention 数学留给前置课程。
- **128 bytes/token 被误记为真实模型常数** → 每次显示结果都并列原始维度与公式，迁移评估强制更换 KV heads 和 dtype。
- **教学物理池被误读成 GPU allocator** → 使用 token unit 和逻辑地址，显式区分稳定原理、教学假设与必须实测的分配/复制行为。
- **最大预留或连续扩容被写成错误答案** → 先展示各自维护的稳定地址、简单边界或节省预留等真实价值，再由固定事件暴露不能同时满足的条件。
- **搬迁状态过多导致图示像调试器** → 每一步只改变一个所有权事实，主读数固定为权威地址、在途读取、有效/保留与最大连续空闲区间。
- **碎片推导提前滑入分页实现** → 本章只形成逻辑索引、读取、发布与回收合同；任何 block/page 数据结构和访问间接层留在第 04 章。
- **公式、图和评估数字漂移** → 所有派生结果来自同一纯函数 fixture，测试从原始维度和区间独立复算关键值。
