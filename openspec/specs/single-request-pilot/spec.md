# Single Request Pilot Specification

## Purpose

规定第 01 章如何从一次 API 请求连续推导出自回归执行、请求状态和资源生命周期，并用有限但真实的工程分析建立后续 KV 与调度章节的共同基础。

## Requirements

### Requirement: 从 API 合同进入自回归循环
章节 SHALL 从用户可见的一次生成请求开始，解释输入、生成参数、停止条件和输出合同，并逐步揭示一次请求为何包含多次模型执行。理解推导所需的 token、Attention 和自回归基础 SHALL 在首次使用处简要补齐或链接复习，不得仅列术语。

#### Scenario: 学习者尚未形成系统视角
- **WHEN** 学习者只知道调用模型会返回文本
- **THEN** 正文通过一个贯穿算例使其能够区分 API 请求、模型前向、生成步和输出 token

### Requirement: Prefill 与 Decode 由依赖关系推导
章节 SHALL 使用同一请求的 token 依赖和张量形状解释 prefill 与 decode 的形成、共同点和差异，再引入术语。正文 MUST 说明二者是执行阶段而非两个独立模型，并为后续 GPU 与 KV 分析保留必要的形状和状态信息。

#### Scenario: 对比两个执行阶段
- **WHEN** 学习者沿同一输入序列推进到首个和后续输出 token
- **THEN** 能够解释每个阶段消费什么、产生什么、哪些计算可并行，以及哪些历史状态会被后续步骤复用

### Requirement: 采样与流式返回不混同于模型执行
章节 SHALL 区分 logits 产生、采样决策、停止判断、文本解码与网络流式发送，说明可见输出时间和生成完成时间不是同一边界。

#### Scenario: 首个 token 已经生成
- **WHEN** 模型产生首个可输出 token 而请求尚未完成
- **THEN** 学习者能够沿事件顺序说明采样、解码、发送和后续 decode 如何继续，并指出客户端可见与服务端资源释放的不同时间点

### Requirement: 请求状态覆盖所有终止路径
章节 SHALL 给出最小但完整的请求状态、允许转换和资源所有权，覆盖正常完成、停止条件、取消、超时与执行失败。任一终止路径 MUST 到达可解释的清理结果，不得只讲正常流程。

#### Scenario: Decode 中途取消
- **WHEN** 请求已持有生成状态并在 decode 期间收到取消
- **THEN** 状态演化明确停止新的计算与输出，并列出队列位置、缓存状态和流对象的释放责任

#### Scenario: 终止与输出并发发生
- **WHEN** 停止判断、流式发送和取消信号在相邻事件中出现
- **THEN** 工程分析给出合法事件顺序、幂等边界和避免重复释放或多发 token 的约束

### Requirement: 工程分析说明最小实现而不伪装成最佳实践
章节 SHALL 使用伪代码、状态转换或接口合同说明一个最小请求执行器如何组织控制流，同时指出同步教学实现省略的并发、批处理、设备异步和资源管理问题。正文 MUST 把这些省略项自然转交给后续章节，而不是提前给出框架优化清单。

#### Scenario: 阅读最小执行循环
- **WHEN** 学习者检查正文中的执行器设计
- **THEN** 能够将每段控制流映射到前文模型语义，并列出该设计进入多请求服务前会遇到的首批问题

### Requirement: 状态轨迹实践保持从属和可移除
章节 MAY 提供一个确定性的请求状态轨迹实践，用于比较正常完成与中途取消的事件、状态和资源变化。实践 SHALL 位于完整正文推导之后，不引入正文未解释的新概念，并且移除实践不影响章节知识链成立。

#### Scenario: 学习者进行状态推演
- **WHEN** 学习者先预测一个取消场景的终态并推进事件
- **THEN** 实践展示原子事件、状态转换和资源所有权变化，并要求学习者解释第一处预测偏差而不是奖励完成点击

### Requirement: 章节验收检查迁移能力
章节 SHALL 以少量综合问题检查学习者能否重建请求时间线、分析异常终止并审查一个朴素执行器。验收不得按小节逐项重复结论，也不得要求背诵 vLLM 或 SGLang 的类型名称。

#### Scenario: 完成章节验收
- **WHEN** 学习者提交对新请求场景的解释与设计判断
- **THEN** 反馈分别检查事件边界、因果关系、资源所有权和结论边界，并指出应回到正文的具体推理缺口
